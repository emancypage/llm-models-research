# Token exposure and benchmark score changes

Post hoc analysis after closeout (26 November 2026, exploratory). The tables compare the original model (S) with its 500 selected output rows (D500) and with its single random draw of 500 output rows (KR500). Rows are token IDs in a model-specific vocabulary. The edit scaled their output weights by 0.1. The four scope checks found zero modified input rows and identical other tensors. [Browse the tables](tables.md) · [Machine-readable summary](summary.json) · [Weight-scope checks](../../scope-checks/quality-restorations.json)

## GSM8K

Each model answered the first 400 public GSM8K test questions. The extractor verified the complete reference solution and final target against the saved samples at both 256 and 1024 new tokens. It tokenized the full reference (including the `####` marker and final number) and separately the trimmed final number exactly as printed. A token counts only when its ID is on the corresponding edit list. Different spellings or tokenizations of the same value can have different exposure. A loss starts from an originally correct answer. A gain starts from an originally incorrect one. Both use the published flexible numeric extraction. The tables give the total group size and the number originally correct alongside the paired losses and gains. [Exposure and output counts per item](gsm8k-items.jsonl) · [Original scores](../../quality-items.csv)

The five Llama D500 tokens named in the review were `00`, `26`, `36`, `64` and `75`. The other five digit-only tokens were `123`, `273`, `741`, `800` and `825`. At 1024 tokens, the five-token group contained 42 of 52 losses in the full solutions. Ten losses occurred among 283 originally correct unexposed items. When the five appeared in the reference final number, 15/16 originally correct items lost credit. Using all ten, the corresponding final-number count was 17/19. The two sets have their own rows in the tables. [GSM8K at 1024 tokens](tables.md#gsm8k-at-1024-tokens) · [Full token inventories](inventory.json)

The output check re-tokenized saved answer texts. The records contain decoded text rather than the generation-time ID sequence, so the counts describe the canonical tokenization of the saved text. Neither model's 400 edited outputs contained a D500 source ID at either limit. Among random-list source IDs, Llama's edited answers contained none. Qwen's contained only `)` (ID 8), three occurrences at 256 tokens and ten at 1024, each in a different answer at that limit. The original and edited counts, including each digit, are recorded by ID. [Answer counts](tables.md#listed-ids-in-re-tokenized-gsm8k-answers) · [Per-ID counts](summary.json) · [Numerical examples](examples.json)

The repeat used the first 200 questions at 256 tokens on each unchanged model. Llama had two losses and one gain. Qwen had five losses and three gains. Restricting Llama to the 162 questions with none of its ten D500 number tokens in the full reference leaves 142 originally correct. The D500 edit had four losses and two gains on these items. The original repeat had two losses and one gain. Using just the five review tokens, 166 of the same 200 items were unexposed, and 145 were originally correct. D500 had five losses and two gains there. The original repeat had two losses and one gain. At 1024 tokens, the group unexposed to all ten had seven losses among 277 originally correct items. Differences in sample size, answer limit and type of change prevent subtracting the repeat count from the 1024-token result. [Repeat observations](repeat-items.csv) · [Grouped counts](summary.json)

## Token categories and scored choices

Categories are counted independently. Digit tokens contain only ASCII digits after trimming whitespace. Answer letters are uppercase A–D after trimming. The MMLU letter column counts exact continuation IDs, including their leading space. Punctuation contains only Unicode punctuation after trimming. Whitespace-only pieces contain no other character. The separate newline column counts any piece containing a newline. Short tokens use the length of the untrimmed decoded string in Unicode characters. Alphabetic words or pieces contain only letters after trimming and include single letters and fragments. These categories overlap. Token counts paired with model and ID preserve the distinction between ` B`, ` a` and ` d`. [Category table](tables.md#categories-in-each-list) · [Raw inventory of decoded IDs](inventory.json)

The extractor preserved the prompt and the exact continuation boundary in the saved lm-eval arguments. MMLU used 1,430 questions per model and four single-token continuations per question. Actual chosen letters were recovered from their log likelihoods. The gold letter was compared with the chosen letter under each version. ARC-Challenge used all 1,172 questions per model. Its recorded `acc_norm` chooses the answer with the highest log likelihood divided by the original answer text's character count. For each option, the extractor flagged any listed token ID in the scored continuation. It matched every reconstructed verdict to the saved metric and the published item score. The ARC groups distinguish the correct option, any incorrect option, and the incorrect option actually selected on a loss.
